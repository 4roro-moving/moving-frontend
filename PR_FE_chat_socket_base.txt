# 작업 내용

- 채팅 기능 도입을 위한 Socket.IO 클라이언트 기본 골격을 추가했습니다.
- 공통 소켓 인스턴스 생성 로직, Zustand 기반 연결 상태 store, 채팅 소켓 hook을 추가했습니다.
- 로컬 개발 환경에서 소켓 서버 주소를 명시할 수 있도록 .env.example에 NEXT_PUBLIC_SOCKET_URL을 추가했습니다.

---

# 변경 사항

- src/lib/socket/socket.ts
  - socket.io-client 기반 공통 소켓 인스턴스를 생성합니다.
  - NEXT_PUBLIC_SOCKET_URL이 있으면 해당 값을 우선 사용합니다.
  - NEXT_PUBLIC_SOCKET_URL이 없으면 NEXT_PUBLIC_API_BASE_URL 또는 NEXT_PUBLIC_API_URL에서 /api suffix를 제거해 소켓 서버 URL을 추론합니다.
  - 소켓 handshake auth 옵션에 현재 access token을 전달합니다.
  - autoConnect: false로 설정해 필요한 시점에 명시적으로 연결하도록 했습니다.

- src/stores/useSocketStore.ts
  - Zustand로 socket 인스턴스와 isConnected 상태를 관리합니다.
  - connect 호출 시 connect/disconnect 이벤트 리스너를 등록합니다.
  - 기존 동일 이벤트 리스너를 off한 뒤 다시 등록해 중복 등록을 방지합니다.

- src/hooks/useChatSocket.ts
  - 채팅 화면에서 사용할 소켓 연결 hook 골격을 추가했습니다.
  - unmount 시 채팅 관련 이벤트 리스너를 정리하도록 했습니다.

- .env.example
  - NEXT_PUBLIC_SOCKET_URL=http://localhost:5000 추가

# To Reviewer

- 이번 PR은 채팅 화면 구현이 아니라 Socket.IO 클라이언트 기본 골격 추가 범위입니다.
- 실제 채팅방 입장, 메시지 조회, 메시지 송수신, 재연결 시 누락 메시지 복구는 후속 PR에서 구현 예정입니다.
- BE 소켓 서버에서는 handshake auth.token으로 access token을 검증하는 구조를 전제로 합니다.
- 팀원 로컬 환경에서는 .env에 NEXT_PUBLIC_SOCKET_URL=http://localhost:5000 값을 추가해야 합니다.
- 배포 환경에서는 API URL과 소켓 URL이 다를 수 있으므로 NEXT_PUBLIC_SOCKET_URL 환경 변수를 별도로 설정해야 합니다.
- 현재 access token은 메모리에서 관리되므로, 새로고침 직후 인증 복구가 완료된 뒤 소켓 연결이 시도되어야 합니다. 채팅 화면 연동 시 AuthProvider/checkAuth 완료 흐름과 함께 확인이 필요합니다.
